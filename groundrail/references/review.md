# Review

仅在 GroundRail 进入 Fact Review、Plan Review 或 Code Review 时读取本文件。Review 是稳定工件上的对抗性只读检查，不是每次保存后的流程动作，也不替代主 Agent 的判断。

## 触发与隔离

自动 Review 的对象仅包括：

- 作为独立交付物、已持久化或高风险的 Fact；低风险内联 Fact 可并入随后必做的 Plan Review。
- 完整 Plan，包括用户已有且准备继续执行的计划。
- 能代表计划范围且已完成相关验证的稳定 diff 或代码改动整体。

仅被读取的 README、AGENTS、源码文档、空白模板和未形成稳定整体的中间保存不触发 Review。

Reviewer 必须使用不含主 Agent 推理历史的干净上下文，并保持只读。若宿主无法提供独立上下文，可做明确标注的隔离复查供参考，但它不满足强制检查点；应停在当前门槛并报告限制，不能用同上下文自审冒充通过。

## Reviewer 契约包

主 Agent 只提供完成判断所需的最小完整输入：

- 原始需求、已确认的验收、非目标和用户决定。
- Review 类型、稳定工件及明确的审查边界。
- 相关 Fact 与来源；若审查代码，附已审 Plan 或等价契约。
- 仓库根目录、仓库指令，以及允许读取的相关和相邻源码范围。
- 已运行的验证命令、真实结果和仍未覆盖的风险。

不要把主 Agent 的诊断、预期结论、可疑点或拟议修复方向作为提示塞给 Reviewer。允许 Reviewer 自行打开契约包引用的工件和相邻代码；干净上下文不等于贫乏上下文。

## 审查轴

- **Contract / Intent**：工件是否满足原始需求、验收、范围、非目标和用户决策边界。
- **Correctness / Safety**：逻辑、边界条件、失败模式、回归、安全和数据完整性是否成立。
- **Repository Shape / Code health**：是否复用已有实现、符合仓库惯例，并避免重复、无收益抽象、过度耦合和范围蔓延。
- **Verification**：验证是否真实运行、能命中目标行为，并覆盖工件所声称的范围。

不同 Review 另加以下重点：

- **Fact Review**：来源是否可追溯；否定结果是否有搜索边界；未知是否仍标为缺口；现有证据是否足以进入目标阶段。
- **Plan Review**：结论是否由 Fact 支持；根因与假设是否分开；复用点、步骤、验证和用户决定是否足以约束实施。
- **Code Review**：稳定 diff 是否实现已审 Plan；触达区域是否引入回归、无收益复杂度或未声明的公共契约、数据、依赖、存储和并发变化。

## 严重级别

- `P0`：阻塞目标的重大正确性、安全、权限或数据问题。
- `P1`：会造成重要缺陷、明确回归风险、关键遗漏或重复造轮子的问题。
- `P2`：低影响的鲁棒性、可维护性或风格改进，最多三项。

只报告有具体位置或证据、影响明确且可执行的问题。不要用严重级别表达个人偏好，也不要把缺少上下文直接升级成缺陷。

## Reviewer Prompt

```text
对抗性只读审查。依据 CONTRACT 判断 ARTIFACT 会在哪里失败；不要总结或修改。
可在给定仓库范围内读取引用及相邻代码。只报告有证据、可执行的问题。
每项输出：严重级别、审查轴、位置/证据、影响、最小修复方向、置信度。
若无问题，明确说明未发现 P0/P1。Fact Review 另列已覆盖面、未覆盖面及其是否阻止目标阶段。
```

## 主 Agent 仲裁

Reviewer 输出是证据，不是裁决。主 Agent 逐项核对并分类：

- `accept`：证据成立；在既有授权范围内处理 P0/P1。
- `reject`：有反证或不属于契约范围；记录简短理由。
- `needs-context`：补充最小证据后重新分类，不能带着该状态越过检查点。
- `user-decision`：涉及需求、范围、风险、成本或不可逆取舍；交给用户决定。

P2 默认只报告；仅当已审授权覆盖、收益明确且不扩大范围时选择性处理。只读代码审查只报告，不修复。

工件发生实质修改后，使用同类型 Reviewer 审查新稳定版本；不要重复审查未变化版本。若同一问题再次出现，只有在下一步没有新证据或只能猜测性扩大范围时才停止并报告。

Review 通过要求没有未决 P0/P1；`needs-context` 必须完成分类，影响执行边界的 `user-decision` 必须取得用户决定。只读审查的完成条件是报告已交付，不要求被审代码本身无问题。
