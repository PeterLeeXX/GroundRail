# Delegation

仅在准备使用子代理、独立上下文或后台研究时读取本文件。委派用于换取独立证据、并行吞吐或干净审查上下文，不是默认拆分任务的仪式。

## 所有权

主 Agent 始终保留：

- 从 Fact 到 Plan 再到 Execute 的阶段判断。
- 不同证据、实现和 Reviewer 意见之间的冲突消解。
- 用户决策与授权边界的解释。
- Reviewer 仲裁、最终综合和对用户的交付。

适合委派的是耗时研究、宽仓库扫描、独立假设验证、机械修改、边界清楚的实现或独立验证。小任务、强耦合链路、直接阻塞下一步的调查，以及主 Agent 已能低成本完成的工作应留在主上下文。

Researcher、Reviewer 和 Executor 是职责，不是固定代理类型；按宿主能力映射到独立上下文、子代理或等价机制。没有可并行工作或独立上下文不能提高质量时，不为形式启动委派。

## 委派契约

每次委派至少说明：

- 单一、可验证的目标和为什么值得独立处理。
- 必要输入、仓库根目录、仓库指令和允许读取的范围。
- 明确的写入边界；默认只返回结果，不写工作区。
- 期望输出、验证方式、完成条件和停止条件。
- 已知事实与用户决定，但不提供主 Agent 希望其证明的结论。

只授予完成子任务所需的最小权限。涉及额外外部写入、生产系统、凭据、破坏性操作或费用时，原任务授权不会自动扩张；停下并取得相应权限。

## 文件所有权与并发

- 子代理默认不写稳定工件；需要写入时，为其分配一个明确且排他的文件或路径。
- 写入前确认目标不存在或属于本任务；不得覆盖未知文件。
- 不让多个执行者同时修改同一文件或强耦合文件集。
- 子代理完成后，主 Agent 检查实际产物、diff 和验证结果；摘要不能替代源码或工件证据。
- 发现所有权冲突、范围扩张或无法继续验证时立即停止，不通过猜测合并结果。

## Researcher

当当前 Fact 依赖仓库内无法建立的外部契约、版本、规范或运行状态时才启动外部研究。Researcher 必须：

- 使用真正拥有该事实的一手来源，例如官方文档、规范、源码或第一方 API。
- 将每项主张紧邻来源引用，明确区分来源事实、推断和仍未知内容。
- 将结果写入单个 Markdown 文件；优先使用仓库既有研究目录，否则使用 `tasks/<task-slug>/research.md`。
- 获得该研究文件的排他写权限，并返回实际路径、覆盖范围和缺口。

研究结果只是 Fact 输入。主 Agent 必须读取工件，核对它与本地代码、实际版本和运行证据的边界及冲突，不能把研究摘要直接升级为诊断或 Plan。

## Reviewer

Reviewer 必须拥有干净上下文并保持只读。委派前按 [Review](review.md) 组织最小完整契约包；不得传递主 Agent 的预期结论。无法取得独立上下文时，遵守 Review 的降级和停止规则。

## Executor

只在 Plan 已审且修改已获授权、文件边界独立、验证明确时委派 Executor。除通用委派契约外，还要提供：

- 已审 Plan、允许改动的文件或模块、非目标和不得改变的公共契约。
- 要运行的验证命令，以及失败或出现新事实时的停止条件。
- 与其他执行者互斥的文件所有权。

Executor 不得自行扩大范围。实质新事实应返回主 Agent 重开 Fact；重大方案变化应停止并重开 Plan，而不是在子任务内隐式改写授权。

## 返回与整合

子代理返回应简洁列出：完成了什么、关键证据或文件位置、实际运行的验证及结果、未解决缺口、是否触发停止条件。主 Agent 基于原始工件和可观察结果整合，不仅依据成功声明。
